## Сцены

Таймкоды округлены до секунды.

| Время | Сцена | Что фактически показано |
|---|---|---|
| `00:00–00:13` | Вводный титр | «КПД производства квадрокоптеров», P0-Demo, живой браузер, только синтетические данные |
| `00:13–00:43` | Подготовка объекта | Admin через реальный экран «Маршруты и новые QR» создаёт уникальный WIP на опубликованном маршруте |
| `00:43–01:15` | Пайка и сборка | Работники `solder` и `assembly2` сканируют тот же QR; интерфейс показывает ряд/операцию и ждёт server acknowledgement |
| `01:15–02:22` | ОТК и брак | QC сканирует WIP, выбирает «Брак», серверную DEMO-причину и получает атомарно сохранённое решение |
| `02:04–02:22` | Открытие переделки | После брака отдельно выбирается разрешённая операция «Сборка» и вводится синтетическая причина; переделка не открывается скрыто |
| `02:22–02:53` | Повторная операция | `assembly2` повторно сканирует WIP; сервер явно выбирает режим «Переделка», primary count не получает второй кредит |
| `02:53–03:25` | Повторный контроль | QC повторно сканирует WIP и фиксирует «Годен · повторно»; история сохраняет исходный брак и новый результат |
| `03:25–03:44` | Отчёт | Supervisor открывает живой отчёт: `A_plan`, `A_volume`, труд, качество, расчётный KPI и причины отсутствия официального результата |
| `03:44–04:00` | Бригадир | Короткий read-only обзор собственного ряда: назначения, выпуск, сохранённые проблемы и переделки |
| `04:00–04:09` | Финальный титр | QR сценария, синтетический статус и явная оговорка «не промышленное внедрение» |

Сборочная операция сценария выполнена на ряду «Сборка 2». Демо-бригадир закреплён за «Сборкой 1», поэтому финальный экран бригадира — отдельная демонстрация role-scoped workspace, а не очередь переделки показанного WIP. Пустой блок переделок ряда 1 не трактуется как состояние WIP ряда 2.

## Воспроизведение

Предусловия:

1. API `http://127.0.0.1:8010/api/v1/health/ready` отвечает `ready`.
2. UI `http://127.0.0.1:5173` отвечает HTTP 200.
3. В demo seed доступны роли `admin`, `solder`, `assembly2`, `qc`, `supervisor`, `foreman` и опубликованный маршрут.
4. В текущем браузерном профиле нет незавершённого worker/QC pending.

Команды из `frontend/`:

```text
npm run record:portfolio
npm run inspect:portfolio-video
```

Recorder: `frontend/scripts/record-portfolio-demo.mjs`. Он создаёт новый уникальный `DEMO-VIDEO-*` WIP, выполняет действия через UI, ждёт фактические серверные ответы и сохраняет итоговый файл только после полного успеха. Неудачный повтор сохраняется в `frontend/test-results/portfolio-video/failed-*.webm` и не перезаписывает принятый артефакт.

Inspector: `frontend/scripts/inspect-portfolio-video.mjs`. Он читает медиаметаданные браузером и сохраняет диагностические кадры в `frontend/test-results/portfolio-video/keyframes/`.
